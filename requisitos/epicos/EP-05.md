# EP-05 — Armazenar e sincronizar registros

## Objetivo

Este épico tem como objetivo garantir que os registros produzidos pelo agente sejam armazenados com segurança e enviados ao backend sem perda de informações.

O sistema deve manter os registros localmente enquanto não houver confirmação do servidor e realizar a sincronização dos dados quando a comunicação estiver disponível.

## Requisitos Funcionais

* RF-18, RF-19.

## Regras de Negócio

* RN-12.

## Requisitos Não Funcionais

* RNF-03, RNF-08, RNF-09, RNF-10.

## Critérios de Aceite relacionados

* CA-05 — Armazenamento e sincronização.
* CA-09 — Privacidade e segurança.

## Escopo

Este épico contempla:

* armazenar localmente os registros produzidos pelo agente;
* manter registros pendentes até confirmação do backend;
* enviar registros ao servidor;
* identificar falhas de comunicação;
* manter os registros quando ocorrer falha no envio;
* retomar a sincronização quando a comunicação for restabelecida;
* marcar registros como sincronizados somente após confirmação do servidor;
* manter os registros sincronizados disponíveis para o histórico conforme a política de retenção;
* evitar perda e duplicação indevida de registros;
* proteger os dados armazenados localmente.

## User Stories

### US-01 — Armazenar registros localmente

**Como** Agente Desktop
**Quero** armazenar localmente os registros produzidos pelo agente
**Para** evitar perda de informações antes da confirmação do servidor.

#### Resultado esperado

Todo registro produzido pelo agente deve permanecer armazenado localmente enquanto não houver confirmação de que foi recebido corretamente pelo backend.

#### Tarefas

* [ ] TASK-01 — Criar estrutura de armazenamento local.
* [ ] TASK-02 — Salvar os registros produzidos pelo agente.
* [ ] TASK-03 — Identificar registros pendentes de sincronização.
* [ ] TASK-04 — Manter o registro armazenado até confirmação do servidor.
* [ ] TASK-05 — Restringir o acesso aos registros locais.

### US-02 — Enviar registros ao backend

**Como** Agente Desktop
**Quero** enviar os registros produzidos pelo agente ao backend
**Para** disponibilizar as informações para o restante do sistema.

#### Resultado esperado

O agente deve enviar os registros pendentes ao backend sempre que houver comunicação disponível.

O registro somente deve ser considerado sincronizado após uma resposta de confirmação do servidor.

#### Tarefas

* [ ] TASK-06 — Buscar registros pendentes.
* [ ] TASK-07 — Preparar os registros para envio.
* [ ] TASK-08 — Enviar os registros ao backend.
* [ ] TASK-09 — Receber a confirmação do servidor.
* [ ] TASK-10 — Marcar o registro local como sincronizado após confirmação.
* [ ] TASK-11 — Manter o registro pendente caso não exista confirmação.

### US-03 — Recuperar sincronização após falha

**Como** Agente Desktop
**Quero** manter os registros quando ocorrer uma falha de comunicação
**Para** que nenhuma atividade seja perdida.

#### Resultado esperado

Quando o agente não conseguir se comunicar com o backend, os registros devem permanecer armazenados localmente.

Quando a comunicação for restabelecida, o sistema deve retomar o envio dos registros pendentes.

#### Tarefas

* [ ] TASK-12 — Identificar falha na comunicação com o backend.
* [ ] TASK-13 — Manter os registros pendentes armazenados.
* [ ] TASK-14 — Identificar o restabelecimento da comunicação.
* [ ] TASK-15 — Buscar registros ainda não sincronizados.
* [ ] TASK-16 — Retomar o envio dos registros.
* [ ] TASK-17 — Confirmar a sincronização dos registros enviados.

### US-04 — Garantir integridade da sincronização

**Como** sistema
**Quero** controlar os registros enviados e pendentes
**Para** evitar perda, inconsistência ou duplicação de informações.

#### Resultado esperado

A sincronização deve garantir que cada registro seja tratado corretamente durante o envio.

Uma falha ou nova tentativa de sincronização não deve provocar perda ou duplicação indevida dos dados.

#### Tarefas

* [ ] TASK-18 — Identificar individualmente os registros.
* [ ] TASK-19 — Controlar o estado de sincronização de cada registro.
* [ ] TASK-20 — Evitar a marcação como sincronizado antes da confirmação do servidor.
* [ ] TASK-21 — Evitar duplicações durante novas tentativas de envio.
* [ ] TASK-22 — Validar a integridade dos registros sincronizados.

## Definição de concluído

O épico é considerado concluído quando:

* [ ] os registros produzidos forem armazenados localmente;
* [ ] registros pendentes permanecerem disponíveis até confirmação do backend;
* [ ] os registros puderem ser enviados ao servidor;
* [ ] falhas de comunicação não provocarem perda de dados;
* [ ] a sincronização for retomada após o restabelecimento da comunicação;
* [ ] registros forem marcados como sincronizados somente após confirmação;
* [ ] registros sincronizados permanecerem disponíveis para o histórico conforme a política de retenção;
* [ ] não ocorrerem duplicações indevidas durante a sincronização;
* [ ] o armazenamento local estiver protegido;
* [ ] os critérios de aceite relacionados forem atendidos;
* [ ] os testes necessários forem executados;
* [ ] a documentação relacionada estiver atualizada.
