# EP-02 — Criar e gerenciar tasks

## Objetivo

Este épico tem como objetivo permitir que o gestor crie e gerencie as tasks utilizadas no Time Tracker.

Cada task deve possuir uma descrição, colaboradores associados e as aplicações ou serviços relacionados ao seu escopo.

## Requisitos Funcionais

* RF-06, RF-07, RF-11.

## Regras de Negócio

* RN-03, RN-04, RN-07.

## Requisitos Não Funcionais

* RNF-05, RNF-12.

## Critérios de Aceite relacionados

* CA-02 — Tasks e início do monitoramento.
* CA-03 — Monitoramento da atividade (parcial: alteração do escopo da task).

## Escopo

Este épico contempla:

* criar uma nova task;
* informar a descrição da task;
* selecionar colaboradores associados;
* definir aplicações ou serviços relacionados à task;
* editar uma task existente;
* informar o colaborador antes de aplicar alterações no escopo de uma task ativa;
* consultar as tasks cadastradas;
* disponibilizar a task somente aos colaboradores associados;
* permitir que o colaborador visualize as tasks atribuídas a ele.

## User Stories

### US-01 — Criar task

**Como** gestor
**Quero** criar uma task
**Para** que eu possa definir uma atividade que será realizada pelos colaboradores.

#### Resultado esperado

O gestor deve conseguir criar uma nova task informando:

* descrição;
* colaboradores associados;
* aplicações ou serviços relacionados.

Após o cadastro, a task deve ficar disponível para os colaboradores selecionados.

#### Tarefas

* [ ] TASK-01 — Criar interface de cadastro da task.
* [ ] TASK-02 — Permitir informar a descrição.
* [ ] TASK-03 — Permitir selecionar colaboradores associados.
* [ ] TASK-04 — Permitir definir aplicações ou serviços relacionados.
* [ ] TASK-05 — Validar as informações da task.
* [ ] TASK-06 — Salvar a task.
* [ ] TASK-07 — Disponibilizar a task aos colaboradores associados.

### US-02 — Editar task

**Como** gestor
**Quero** editar uma task existente
**Para** que eu possa atualizar suas informações quando necessário.

#### Resultado esperado

O gestor deve conseguir alterar as informações de uma task existente.

Podem ser alterados:

* descrição;
* colaboradores associados;
* aplicações ou serviços relacionados.

Quando as aplicações ou os serviços de uma task ativa forem alterados, o Agente Desktop deve informar o colaborador antes de aplicar o novo escopo.

#### Tarefas

* [ ] TASK-08 — Permitir selecionar uma task existente.
* [ ] TASK-09 — Carregar as informações da task.
* [ ] TASK-10 — Permitir alterar a descrição.
* [ ] TASK-11 — Permitir alterar os colaboradores associados.
* [ ] TASK-12 — Permitir alterar as aplicações ou serviços relacionados.
* [ ] TASK-13 — Validar as alterações.
* [ ] TASK-14 — Salvar as alterações realizadas.
* [ ] TASK-15 — Informar o colaborador antes de aplicar alterações no escopo de uma task ativa.

### US-03 — Consultar tasks

**Como** gestor
**Quero** consultar as tasks cadastradas
**Para** que eu possa acompanhar e gerenciar as atividades criadas.

#### Resultado esperado

O Dashboard deve apresentar ao gestor as tasks que ele pode administrar.

Cada task deve apresentar as informações necessárias para sua identificação e gerenciamento.

#### Tarefas

* [ ] TASK-16 — Buscar as tasks disponíveis para o gestor.
* [ ] TASK-17 — Criar visualização da lista de tasks.
* [ ] TASK-18 — Exibir as principais informações de cada task.
* [ ] TASK-19 — Permitir selecionar uma task para consulta ou edição.

### US-04 — Visualizar tasks atribuídas

**Como** colaborador
**Quero** visualizar as tasks atribuídas a mim
**Para** que eu possa selecionar a atividade que irei executar.

#### Resultado esperado

O Agente Desktop deve apresentar somente as tasks às quais o colaborador estiver associado.

Tasks que não estejam atribuídas ao colaborador não devem ser exibidas.

#### Tarefas

* [ ] TASK-20 — Identificar o colaborador registrado no agente.
* [ ] TASK-21 — Buscar as tasks associadas ao colaborador.
* [ ] TASK-22 — Exibir as tasks disponíveis no Agente Desktop.
* [ ] TASK-23 — Garantir que tasks não atribuídas não sejam exibidas.

## Definição de concluído

O épico é considerado concluído quando:

* [ ] o gestor puder criar uma task;
* [ ] a task possuir descrição, colaboradores e aplicações ou serviços relacionados;
* [ ] o gestor puder editar uma task existente;
* [ ] alterações no escopo de uma task ativa forem informadas ao colaborador antes de sua aplicação;
* [ ] o gestor puder consultar suas tasks;
* [ ] somente colaboradores associados puderem visualizar a task;
* [ ] o colaborador visualizar somente as tasks atribuídas a ele;
* [ ] os critérios aplicáveis do CA-02 e do CA-03 forem atendidos;
* [ ] os testes necessários forem executados;
* [ ] a documentação relacionada estiver atualizada.
